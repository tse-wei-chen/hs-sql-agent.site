## 2.0.3의 주요 변경점

2.0.3은 기존 SQL 및 보안 경계를 유지하면서 Hosting 방식과 DML 승인 통합을 확장합니다.

- `HsSqlAgent.Hosting`은 첫 번째 제공 ToolBox / Docker와 같은 완전한 ASP.NET Core 구성을 제공합니다.
- `HsSqlAgent.Server`는 인증, 권한 부여, 관리 UI, Middleware 순서, 텔레메트리 또는 승인 구성을 애플리케이션이 직접 소유해야 할 때 사용하는 모듈형 패키지입니다.
- `execute_dml_sql`은 세미콜론으로 구분된 하나 이상의 `UPDATE`, `DELETE`, `INSERT ... VALUES` 문을 받을 수 있습니다. 여러 문은 한 번 승인되고 원래 순서대로 하나의 트랜잭션에서 원자적으로 commit됩니다. **별도의 batch MCP tool은 추가되지 않습니다.**
- DML 승인은 `IDmlApprovalProvider`를 통해 transport와 분리되며 승인, 거절 또는 비동기 완료를 위한 `Pending`을 반환할 수 있습니다.
- `HsSqlAgent.Approvals.Webhook`은 공식 범용 비동기 adapter입니다. SQL 검증, 승인 fingerprint 결합, 현재 상태 재검증, 최종 commit은 계속 HsSqlAgent가 소유합니다.

<Callout type="warning" title="업그레이드 전에 Admin Store를 백업하세요">
Admin Store capability가 있으면 Pending 영속 승인이 HsSqlAgent 영속화 계층을 사용합니다. control-plane database와 보호된 키 자료를 폐기 가능한 cache가 아니라 업그레이드 상태로 다루세요.
</Callout>

## Hosting 경로를 명확히 선택하기

독립 서비스는 공식 Docker image를 계속 사용합니다. .NET host에 동일한 완전 구성을 넣으려면 `HsSqlAgent.Hosting`과 `AddHsSqlAgentStandardHost()` / `UseHsSqlAgentStandardHost()`를 사용합니다. 개별 capability를 교체하려면 `HsSqlAgent.Server`와 `AddHsSqlAgent*` API를 사용합니다.

## Safe DML 다시 검증하기

비운영 database에서 단일 문과 다중 문 트랜잭션을 각각 테스트하고 승인, 거절, 실패 시 rollback, commit 직전 재검증을 확인하세요. 비동기 provider를 사용하면 중복 callback, 만료, stale approval completion도 테스트하세요.

## 구성 확인

표준 Hosting은 `DmlApproval:Provider`로 승인 방식을 선택하며 기본값은 `McpElicitation`입니다. Webhook은 endpoint, callback URL, signing secret도 필요합니다. 모듈형 `HsSqlAgent.Server` host는 DI로 provider를 선택합니다.
