백엔드 서비스나 배포 자동화에서 Custom Tools 관리, 설정 변경 또는 접근 자격 증명 발급이 필요할 때 **관리 API 키**를 사용할 수 있습니다. 각 키에는 선택한 관리 권한만 부여됩니다.

## 키 발급

1. `/runtime/security.edit` 권한이 있는 관리자 계정으로 로그인하고 **Runtime → Management API Keys** 화면을 엽니다.
2. 연동 이름과 만료 시간(최대 365일)을 설정합니다.
3. 연동에 필요한 관리 권한만 선택합니다.
4. 키를 발급하고 한 번만 표시되는 비밀 값을 즉시 복사합니다.

비밀 값은 백엔드의 비밀 관리 시스템에 저장하고 프런트엔드나 소스 저장소에 포함하지 마세요.

## 관리 API 호출

API 호출 시 `X-API-Key` HTTP 헤더에 키를 넣습니다.

```bash
curl "https://agent.example.com/api/CustomSqlTool" \
  -H "X-API-Key: ${HS_MANAGEMENT_API_KEY}"
```

`X-API-Key`와 `Authorization` 헤더를 동시에 보내면 요청이 거부됩니다.

## 주요 작업과 필요한 권한

별도의 연동용 API를 만들 필요 없이 기존 `/api` 엔드포인트를 사용하며, 요청마다 해당 관리 권한을 검사합니다.

| 작업 | API | Canonical Permission |
| --- | --- | --- |
| Custom Tools 목록 조회 | `GET /api/CustomSqlTool` | `/runtime/custom-tools.view` |
| Custom Tool 생성 | `POST /api/CustomSqlTool` | `/runtime/custom-tools.create` |
| Custom Tool 게시 | `POST /api/CustomSqlTool/{id}/publish` | `/runtime/custom-tools.edit` |
| 접근 키 목록 조회 | `GET /api/runtime/mcp-keys` | `/runtime/mcp-keys.view` |
| 접근 키 발급 | `POST /api/runtime/mcp-keys` | `/runtime/mcp-keys.create` |

## 권한 및 키 관리

필요한 최소 권한만 부여하세요. 관리자는 키를 언제든 폐기하거나 교체할 수 있습니다. 교체 시 새 키가 발급되고 기존 키는 즉시 무효화됩니다. 관리 데이터베이스에는 비밀 값 대신 해시가 저장되며, 관리 작업은 `management-api-key` 주체로 감사 기록에 남습니다.

관리 API 키의 발급·교체·폐기는 `/runtime/security.edit` 권한이 있는 로그인 관리자만 수행할 수 있습니다.

> 관리 권한은 특정 데이터베이스 ID나 테넌트로 자동 제한되지 않습니다. 신뢰할 수 있는 백엔드에서 키를 관리하고 서비스별 접근 정책은 연동 시스템에서 적용하세요.

## 배포 요구 사항

키 발급 전에 SQLite 또는 PostgreSQL용 Admin Store 마이그레이션을 적용해 `ManagementApiKeys` 테이블을 생성하세요.
