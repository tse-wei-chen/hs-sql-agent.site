<Callout type="info" title="이미 호스트 애플리케이션을 운영하는 경우가 아니라면 Docker로 시작하세요">
Docker Compose가 가장 짧은 경로입니다. 리포지토리에 service wiring과 environment-variable mapping이 이미 포함되어 있습니다. NuGet 경로는 기존 ASP.NET Core host에 hs-sql-agent를 내장하는 팀을 위한 것입니다.
</Callout>

## Docker Compose

<Steps>
  <Step title="environment file 만들기" description="checked-in example을 복사해 configuration을 명시적이고 review 가능한 상태로 유지합니다.">

```bash
cp .env.example .env
```

  </Step>
  <Step title="signing secret 교체" description="HMAC_KEY와 JWT_KEY에 서로 다른 32 bytes 이상의 unique secret을 설정합니다.">
`.env.example`의 값은 placeholder입니다. 그대로 deploy하지 마세요.
  </Step>
  <Step title="서비스 시작" description="기본 single-instance stack을 실행합니다.">

```bash
docker compose up -d
```

  </Step>
  <Step title="Admin Panel 열기" description="기본 application listener는 port 8080입니다.">
로컬 환경에서는 `http://localhost:8080`을 열고 첫 administrator setup을 완료합니다.
  </Step>
</Steps>

## 첫 MCP key 발급

<Steps>
  <Step title="Runtime → MCP Keys 열기" description="Key는 MCP identity와 authorization boundary입니다." />
  <Step title="database와 tool scope 선택" description="Key를 하나의 Database Management entry에 바인딩하고 client에 필요한 tool만 노출합니다." />
  <Step title="plaintext key 복사" description="lifecycle dialog에 새로 발급된 secret이 표시됩니다. client secret store에 보관하세요." />
  <Step title="생성된 client configuration 사용" description="또는 Streamable HTTP endpoint에 X-MCP-Server-Key로 secret을 보냅니다." />
</Steps>

기본 MCP endpoint는 `/mcp`입니다. 로컬 머신 밖의 client가 접속하는 경우 `MCP_PUBLIC_ENDPOINT`에 `/mcp`를 포함한 외부 접근 가능한 absolute HTTP/HTTPS URL을 설정합니다.

<Callout type="warning" title="DML에는 client Elicitation support가 필요합니다">
MCP tool을 호출할 수 있다는 이유만으로 `execute_dml_sql`을 활성화하지 마세요. 사람이 정확한 mutation impact를 검토하고 승인하려면 client가 호환되는 MCP form Elicitation을 구현해야 합니다.
</Callout>
