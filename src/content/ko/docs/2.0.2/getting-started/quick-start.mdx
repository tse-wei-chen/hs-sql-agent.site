<Callout type="info" title="기존 호스트 애플리케이션에 직접 내장할 필요가 없다면 Docker로 시작하세요">
Docker Compose가 가장 빠른 방법입니다. 저장소에 서비스 연결 구성과 환경 변수 매핑이 이미 포함되어 있습니다. NuGet 방식은 기존 ASP.NET Core 호스트에 hs-sql-agent를 내장하려는 경우에 적합합니다.
</Callout>

## Docker Compose

<Steps>
  <Step title="환경 설정 파일 만들기" description="설정을 명시적으로 관리하고 검토할 수 있도록 저장소의 예제 파일을 복사합니다.">

```bash
cp .env.example .env
```

  </Step>
  <Step title="서명용 비밀값 교체" description="HMAC_KEY와 JWT_KEY에는 서로 다른 32바이트 이상의 고유한 값을 설정합니다.">
`.env.example`의 값은 예시입니다. 그대로 운영 환경에 배포하지 마세요.
  </Step>
  <Step title="서비스 실행" description="기본 단일 인스턴스 구성을 시작합니다.">

```bash
docker compose up -d
```

  </Step>
  <Step title="관리자 화면 열기" description="기본 애플리케이션은 8080 포트에서 수신합니다.">
로컬 환경에서는 `http://localhost:8080`을 열고 첫 관리자 설정을 완료합니다.
  </Step>
</Steps>

## 첫 MCP 키 발급

<Steps>
  <Step title="Runtime → MCP Keys 열기" description="MCP 키는 클라이언트 식별과 권한 검사의 경계입니다." />
  <Step title="데이터베이스와 도구 권한 범위 선택" description="키를 하나의 Database Management 항목에 연결하고 클라이언트에 필요한 도구만 허용합니다." />
  <Step title="평문 키 복사" description="발급 직후 대화상자에 표시되는 비밀값을 복사해 클라이언트의 안전한 비밀 저장소에 보관합니다." />
  <Step title="생성된 클라이언트 설정 사용" description="또는 Streamable HTTP 엔드포인트 요청에 X-MCP-Server-Key 헤더로 비밀값을 전달합니다." />
</Steps>

기본 MCP 엔드포인트는 `/mcp`입니다. 다른 장치에서 접속한다면 `MCP_PUBLIC_ENDPOINT`에 외부에서 접근 가능한 HTTP 또는 HTTPS 절대 URL을 `/mcp`까지 포함해 설정하세요.

<Callout type="warning" title="DML에는 MCP Elicitation 지원이 필요합니다">
클라이언트가 MCP 도구를 호출할 수 있다는 이유만으로 `execute_dml_sql`을 활성화하지 마세요. 사람이 실제 변경 내용을 확인하고 승인할 수 있도록 클라이언트도 MCP form Elicitation을 지원해야 합니다.
</Callout>
