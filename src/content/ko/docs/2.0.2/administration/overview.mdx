## 권장 운영 흐름

<Flow items={["데이터베이스 등록", "MCP 키 발급", "도구/테이블 범위 설정", "메타데이터 보강", "클라이언트 연결", "관찰 및 감사"]} />

1. 에이전트에 노출할 데이터베이스 연결을 등록하고 확인합니다.
2. 해당 데이터베이스에 바인딩된 MCP 키를 발급하고 필요한 도구와 테이블만 허용합니다.
3. 원시 스키마 이름만으로 안정적인 탐색이 어려우면 semantic metadata를 추가합니다.
4. 클라이언트 설정을 생성하고 공개 Streamable HTTP `/mcp` 엔드포인트로 연결합니다.
5. Audit과 Operability 화면에서 런타임 동작을 확인하고 필요에 따라 정책을 강화합니다.

<Callout type="info" title="Admin 인증과 MCP 인증은 별개입니다">
Admin 계정은 제어 평면을 운영합니다. MCP 클라이언트는 MCP 키로 인증합니다. 사용자가 Admin 권한을 가진다고 해서 MCP 자격 증명이 자동 생성되지 않으며, MCP 키가 Admin UI 접근 권한을 제공하지도 않습니다.
</Callout>

## MCP 키 수명 주기

키를 발급·교체·복제하면 UI에서 지원되는 클라이언트 형식에 맞는 Streamable HTTP 설정을 바로 생성할 수 있습니다. 평문 secret은 해당 수명 주기 대화상자에서만 표시되며 이후 다시 조회할 수 있도록 보관되지 않습니다.

대화상자를 닫기 전에 생성된 설정을 복사하십시오.

## 임베디드 UI와 내장 ID는 선택 사항입니다

ASP.NET Core 호스트는 패키지된 Admin UI 없이 HsSqlAgent Admin API만 노출할 수 있습니다. 모듈형 통합에서는 `UseHsSqlAgentAdminApi()`를 사용하고 호스트가 `MapControllers()`를 호출하게 하며, 패키지 UI가 필요할 때만 `UseHsSqlAgentAdminUi()`를 추가합니다.

호스트는 `AddHsSqlAgentHostAuthorization(...)`을 사용해 기존 로그인 및 권한 시스템을 유지할 수도 있습니다. 이 경우 HsSqlAgent의 member, role, JWT, SMTP, OIDC 구성이 필요하지 않습니다. MCP는 `AddHsSqlAgentMcp(...)` / `UseHsSqlAgentMcp()`로 독립적으로 선택하고 매핑합니다.

전체 2.0.2 구성 모델은 [ASP.NET Core 통합](/ko/docs/integration/aspnet-core)을 참고하십시오.
