Diese Seite dokumentiert die **tatsächlich im Quellcode von hs-sql-agent 2.0.1 vorhandenen Controller-Routen**. Die mitgelieferte Admin UI verwendet genau diese Oberfläche.

<Callout type="warning" title="Quellcodevertrag von 2.0.1, kein separat versionierter REST-Standard">
Der Server 2.0.1 veröffentlicht diese Controller nicht unter einem `/v1`-Kompatibilitäts-Namespace. Integrationen außerhalb der mitgelieferten Admin UI sollten die hs-sql-agent-Version festlegen und diese Referenz bei Upgrades erneut prüfen.
</Callout>

## Authentifizierung und Autorisierung

Die meisten Admin-Routen benötigen eine authentifizierte Admin-Identität. Geschützte Laufzeitaktionen prüfen zusätzlich Path/Action-Berechtigungen wie `/runtime/db-management` → `view` oder `/auth/role` → `edit`.

Anonyme Ausnahmen existieren für Abläufe, die vor einer Admin-Sitzung beginnen müssen: First Run, Sign-in/Sign-up, ausgewählte OIDC-Endpunkte, Passwort-Wiederherstellung und Abschluss einer MFA-Challenge.

Siehe [Berechtigungen](/de/docs/administration/permissions).

## Credential-Status

`GET /api/Credential/status` existiert in 2.0.1 und liefert lediglich einen einfachen Status der Credential API. Der Controller selbst besitzt kein `[Authorize]`-Attribut. Behandeln Sie ihn als eng begrenzten Status-Endpunkt, nicht als authentifizierte Credential-Management-API.

## Fehler und Kompatibilität

Die Controller verwenden übliche HTTP-Statuscodes: beispielsweise 400 für Validierung, 401/403 für Authentifizierung/Autorisierung, 404 für fehlende Ressourcen, 409 für widersprüchlichen Tool-/Rollenzustand, 413 für zu große Audit-Exporte und gegebenenfalls 429 bei begrenztem Druck auf SQL-Operationen.

Externe Automatisierung sollte auf 2.0.1 festgelegt werden und das tatsächlich verwendete Response Model prüfen. Diese Seite dokumentiert bewusst Routen und wichtige Verträge, ohne jedes Admin View Model als dauerhaft versioniertes externes SDK darzustellen.
