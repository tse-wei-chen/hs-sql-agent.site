Mit einem **Management-API-Schlüssel** können Backend-Dienste und Bereitstellungsprozesse Custom Tools verwalten, Konfigurationen ändern oder Zugangsdaten ausstellen. Jeder Schlüssel kann nur die ausdrücklich freigegebenen Verwaltungsaktionen ausführen.

## Schlüssel erstellen

1. Melden Sie sich mit der Berechtigung `/runtime/security.edit` an und öffnen Sie **Runtime → Management API Keys**.
2. Geben Sie einen Namen und eine Ablaufzeit (maximal 365 Tage) ein.
3. Wählen Sie die erforderlichen Verwaltungsberechtigungen aus.
4. Stellen Sie den Schlüssel aus und kopieren Sie das einmal angezeigte Geheimnis sofort.

Speichern Sie das Geheimnis im Secrets-Manager des Backends und niemals in Frontend-Code oder Versionsverwaltung.

## Admin-API aufrufen

Senden Sie den Schlüssel im HTTP-Header `X-API-Key`:

```bash
curl "https://agent.example.com/api/CustomSqlTool" \
  -H "X-API-Key: ${HS_MANAGEMENT_API_KEY}"
```

Senden Sie `X-API-Key` nicht zusammen mit einem `Authorization`-Header. Solche Anfragen werden abgelehnt.

## Typische Aktionen und Berechtigungen

Die vorhandenen `/api`-Endpunkte werden direkt verwendet. Für Integrationen ist keine zusätzliche API notwendig; die kanonischen Berechtigungen gelten weiterhin.

| Aktion | API | Canonical Permission |
| --- | --- | --- |
| Custom Tools auflisten | `GET /api/CustomSqlTool` | `/runtime/custom-tools.view` |
| Custom Tool erstellen | `POST /api/CustomSqlTool` | `/runtime/custom-tools.create` |
| Custom Tool veröffentlichen | `POST /api/CustomSqlTool/{id}/publish` | `/runtime/custom-tools.edit` |
| Zugangsschlüssel auflisten | `GET /api/runtime/mcp-keys` | `/runtime/mcp-keys.view` |
| Zugangsschlüssel ausstellen | `POST /api/runtime/mcp-keys` | `/runtime/mcp-keys.create` |

## Berechtigungen und Schlüsselverwaltung

Vergeben Sie nur die wirklich benötigten Berechtigungen. Administratoren können Schlüssel jederzeit widerrufen oder rotieren. Bei der Rotation wird ein neues Geheimnis ausgegeben und der alte Schlüssel sofort gesperrt. Der Admin Store speichert den Hash statt des Klartexts; Aktionen werden unter `management-api-key` protokolliert.

Zum Ausstellen, Rotieren oder Widerrufen von Management-API-Schlüsseln ist eine angemeldete Administration mit `/runtime/security.edit` erforderlich.

> Verwaltungsberechtigungen sind nicht automatisch auf Datenbank-IDs oder Mandanten begrenzt. Bewahren Sie Schlüssel nur in vertrauenswürdigen Backends auf und setzen Sie anwendungsspezifische Zugriffsregeln im integrierenden Dienst um.

## Voraussetzungen für den Betrieb

Führen Sie vor der ersten Schlüsselausstellung die SQLite- oder PostgreSQL-Migration für den Admin Store aus, um `ManagementApiKeys` anzulegen.
