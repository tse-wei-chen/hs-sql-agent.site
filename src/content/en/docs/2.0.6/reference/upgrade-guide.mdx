## 2.0.5 → 2.0.6 (proposed)

This proposed 2.0.6 update adds machine-to-machine management of the existing Admin REST API without requiring interactive login. It does not change the SQL compiler or MCP tool execution protocol.

## Management API Keys

After deploying the new version and applying Admin Store migrations: open the Management API Keys page, create a narrowly permissioned integration key, store its one-time secret, and use `X-API-Key` when calling the authorized `/api` endpoints. Keep human admin requests on JWT and MCP client requests on MCP keys.

```http
X-API-Key: hsa_mgmt_<secret>
```

## Migration and compatibility

The feature adds an Admin Store table, `ManagementApiKeys`, via SQLite and PostgreSQL migrations. Apply the appropriate migration before issuing any key; existing human JWTs and MCP keys remain unchanged.

Existing human JWT sessions, MCP keys, five built-in MCP tools, and SQL security semantics remain unchanged. The new table is additive. If rolling back, revoke affected integration keys first; the earlier version has no Management API Key authentication.

> Do not assume database-ID or SaaS tenant isolation from a canonical management permission. API keys are intended for trusted backends only.
