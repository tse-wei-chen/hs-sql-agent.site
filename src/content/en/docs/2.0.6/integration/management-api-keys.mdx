Use a **Management API Key** when your backend service, deployment pipeline, or another integration needs to administer Custom Tools, configuration, or access credentials. Each key can perform only the management operations you explicitly authorize.

## Create a key

1. Sign in to the Admin Console with the `/runtime/security.edit` permission and open **Runtime → Management API Keys**.
2. Enter an integration name and expiration date (up to 365 days).
3. Select the required canonical management permissions.
4. Issue the key and copy its secret. The secret is shown only once.

Store the secret in a backend secrets manager, never in client-side code or source control.

## Call the Admin API

Send the secret in the `X-API-Key` HTTP header:

```bash
curl "https://agent.example.com/api/CustomSqlTool" \
  -H "X-API-Key: ${HS_MANAGEMENT_API_KEY}"
```

Do not send an `Authorization` header together with `X-API-Key`. A request containing both is rejected.

## Common operations and permissions

Existing `/api` endpoints work without a separate integration API. The usual canonical permissions still apply.

| Operation | API | Canonical Permission |
| --- | --- | --- |
| List Custom Tools | `GET /api/CustomSqlTool` | `/runtime/custom-tools.view` |
| Create a Custom Tool | `POST /api/CustomSqlTool` | `/runtime/custom-tools.create` |
| Publish a Custom Tool | `POST /api/CustomSqlTool/{id}/publish` | `/runtime/custom-tools.edit` |
| List access keys | `GET /api/runtime/mcp-keys` | `/runtime/mcp-keys.view` |
| Issue an access key | `POST /api/runtime/mcp-keys` | `/runtime/mcp-keys.create` |

## Access control and key lifecycle

Grant only the actions the integration needs. An administrator can revoke a key at any time or rotate it to issue a replacement and immediately invalidate the old secret. The Admin Store keeps a hash rather than the plaintext key; management actions are auditable under the `management-api-key` actor.

Issuing, rotating, and revoking Management API Keys requires a signed-in administrator with `/runtime/security.edit`.

> Management permissions are not automatically limited to a database ID or tenant. Keep the secret in a trusted backend and enforce application-specific authorization in your integration.

## Deployment requirements

Apply the Admin Store migration for SQLite or PostgreSQL to create the `ManagementApiKeys` table before issuing keys.

For field-level Request/Response definitions, see the [Admin REST API Contracts](/docs/2.0.6/reference/admin-api-contracts).
