## Recommended operator flow

<Flow items={["Register database", "Issue MCP key", "Set tool/table scope", "Enrich metadata", "Connect client", "Observe & audit"]} />

1. Register and verify the database connection that the agent should expose.
2. Issue an MCP key bound to that database and give it only the tools/tables the client needs.
3. Add semantic metadata when raw schema names are not enough for reliable agent discovery.
4. Generate the client configuration and connect through the public Streamable HTTP `/mcp` endpoint.
5. Use audit and operability surfaces to inspect runtime behavior and tighten policy where needed.

<Callout type="info" title="Admin authentication and MCP authentication are separate">
Admin accounts operate the control plane. MCP clients authenticate with MCP keys. Giving a user Admin access does not automatically create an MCP credential, and an MCP key does not grant access to the Admin UI.
</Callout>

## MCP key lifecycle

When a key is issued, rotated, or duplicated, the UI can generate direct Streamable HTTP configuration for supported client formats. The plaintext secret is shown only in that lifecycle dialog and is not retained for later display.

Copy the generated configuration before closing the dialog.

## Embedded UI is optional for library consumers

When hs-sql-agent is embedded in an ASP.NET Core application, `UseHsSqlAgent()` can expose the API/MCP pipeline without serving the Admin UI. Calling `.ServeAdminUi()` enables the packaged UI as well.

See [ASP.NET Core integration](/en/docs/integration/aspnet-core) for host setup and deployment considerations.
