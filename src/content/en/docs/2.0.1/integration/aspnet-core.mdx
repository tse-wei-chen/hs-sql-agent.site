`HsSqlAgent.Server` can be hosted inside an existing ASP.NET Core application instead of running only as the repository's standalone service.

<CardGrid columns={3}>
  <DocCard title="Package" icon="PKG" description="Install HsSqlAgent.Server into an existing ASP.NET Core host." />
  <DocCard title="API / MCP only" icon="API" description="Use UseHsSqlAgent() when the host should expose the hs-sql-agent API/MCP pipeline without the packaged Admin UI." />
  <DocCard title="Embedded Admin UI" icon="UI" description="Chain .ServeAdminUi() when the same host should also serve the packaged operator interface." />
</CardGrid>

## Minimal setup

<Steps>
  <Step title="Install the package">

```bash
dotnet add package HsSqlAgent.Server
```

  </Step>
  <Step title="Register hs-sql-agent services">

```csharp
builder.Services.AddHsSqlAgent(options =>
{
    // Configure service options here.
});
```

  </Step>
  <Step title="Map the API/MCP pipeline">

```csharp
app.UseHsSqlAgent();
```

`UseHsSqlAgent()` exposes the hs-sql-agent API/MCP pipeline without requiring the packaged Admin UI.
  </Step>
  <Step title="Optionally serve the Admin UI">

```csharp
app.UseHsSqlAgent().ServeAdminUi();
```

Use this form when the application should expose both the runtime endpoints and the packaged Admin UI.
  </Step>
</Steps>

## Pipeline defaults

| Surface | Default |
| --- | --- |
| MCP endpoint | `/mcp` |
| Admin API prefix | `/api` |
| Admin UI request path | `/` |
| Admin UI content root | `wwwroot` |

The service options cover MCP public endpoint, bootstrap settings, enterprise identity, operability, telemetry, admin database, authentication, rate limiting, distributed synchronization, SQL concurrency, DML approval storage, and cache configuration.

<Callout type="warning" title="Embedding does not weaken the security boundary">
Treat the package as the same governed runtime as the standalone server. The host still needs unique HMAC/JWT secrets, an externally correct MCP public endpoint, persistent data-protection keys when required, and the appropriate database/cache/distributed providers for its deployment topology.
</Callout>
