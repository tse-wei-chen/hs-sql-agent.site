当 SaaS 后端、部署流程或其他服务需要自动管理 Custom Tools、更新配置或签发访问凭证时，可以使用**管理 API 密钥**。每把密钥只能执行管理员明确授权的操作。

## 创建密钥

1. 以拥有 `/runtime/security.edit` 权限的管理员身份登录，打开 **Runtime → Management API Keys**。
2. 填写集成名称和过期时间（最长 365 天）。
3. 明确选择需要的管理权限。
4. 签发密钥并立即复制明文；明文只显示一次。

请将密钥保存在后端密钥管理系统中，不要放在前端代码或代码仓库。

## 调用管理 API

调用 API 时，通过 `X-API-Key` HTTP 请求头传递密钥：

```bash
curl "https://agent.example.com/api/CustomSqlTool" \
  -H "X-API-Key: ${HS_MANAGEMENT_API_KEY}"
```

不要同时发送 `X-API-Key` 和 `Authorization` 请求头，否则请求会被拒绝。

## 常见操作及所需权限

直接使用现有 `/api` 管理接口，无需开发额外的集成接口；每次请求仍会检查对应的规范权限。

| 操作 | API | Canonical Permission |
| --- | --- | --- |
| 查看 Custom Tools | `GET /api/CustomSqlTool` | `/runtime/custom-tools.view` |
| 创建 Custom Tool | `POST /api/CustomSqlTool` | `/runtime/custom-tools.create` |
| 发布 Custom Tool | `POST /api/CustomSqlTool/{id}/publish` | `/runtime/custom-tools.edit` |
| 查看访问密钥 | `GET /api/runtime/mcp-keys` | `/runtime/mcp-keys.view` |
| 签发访问密钥 | `POST /api/runtime/mcp-keys` | `/runtime/mcp-keys.create` |

## 权限和密钥管理

只授予集成服务所需的最小权限。管理员可以随时撤销密钥，也可以通过轮换签发新密钥并立即使旧密钥失效。管理数据库只保存哈希，不保存明文；操作以 `management-api-key` 身份记录审计日志。

签发、轮换或撤销管理 API 密钥，需要已登录管理员拥有 `/runtime/security.edit` 权限。

> 管理权限目前不会按数据库 ID 或租户自动限制。请将密钥保存在可信任的后端，并由集成服务自行执行应用层授权。

## 部署要求

签发密钥前，需要执行 SQLite 或 PostgreSQL 的 Admin Store 数据库迁移，创建 `ManagementApiKeys` 表。

请求与响应字段、HTTP 状态码及完整示例，请参阅[管理 REST API 接入规范](/zh-hans/docs/2.0.6/reference/admin-api-contracts)。
