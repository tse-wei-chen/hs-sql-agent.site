管理 API 密钥允许可信任的后端服务无需交互式管理员登录，就能调用已授权的 `/api` 管理接口。它**不是 MCP 访问密钥**，也不是管理员登录令牌。

## 在管理控制台创建密钥

使用具有 `/runtime/security.edit` 权限的管理员账户登录，打开 **运行管理 → Management API Keys**。填写集成服务名称、365 天以内的 UTC 过期时间，并明确勾选需要的管理权限。明文密钥只显示一次，请立即存入后端密钥管理系统，不要放到浏览器或代码仓库。

## Authentication

调用时将密钥放入 `X-API-Key` 请求头。管理员的 JWT 仍使用 `Authorization: Bearer <JWT>`；这两种请求头不能同时使用。

```http
GET /api/runtime/mcp-keys HTTP/1.1
Host: agent.example.com
X-API-Key: hsa_mgmt_<secret>
```

```bash
curl https://agent.example.com/api/runtime/mcp-keys \\
  -H "X-API-Key: ${HS_MANAGEMENT_API_KEY}"
```

## 复用现有管理 API，无需 SaaS 专用接口

集成方可以按授权调用现有 Custom Tool 创建、发布和 MCP 密钥签发接口。供 MCP 客户端执行工具使用的 **MCP 密钥必须单独签发**；管理 API 密钥不能调用 `/mcp`。

| Method | Endpoint | Canonical permission |
| --- | --- | --- |
| `GET` | `/api/runtime/management-api-keys` | `/runtime/security.edit` (human only) |
| `POST` | `/api/runtime/management-api-keys` | `/runtime/security.edit` (human only) |
| `POST` | `/api/runtime/management-api-keys/{id}/rotate` | `/runtime/security.edit` (human only) |
| `POST` | `/api/runtime/management-api-keys/{id}/revoke` | `/runtime/security.edit` (human only) |
| `POST` | `/api/CustomSqlTool` | `/runtime/custom-tools.create` |
| `POST` | `/api/CustomSqlTool/{id}/publish` | `/runtime/custom-tools.edit` |
| `POST` | `/api/runtime/mcp-keys` | `/runtime/mcp-keys.create` |

## 权限与安全边界

每把密钥只能获得明确选择的规范权限（`path.action`）。它不能管理用户、角色、安全策略或其他管理 API 密钥。过期或撤销后立即失效；轮换将签发新密钥并立即撤销旧密钥。管理数据库只保存哈希值，不保存明文；审计身份为 `management-api-key`。

> 管理权限不等于数据库或租户隔离。具有 Custom Tool、MCP 密钥管理权限的密钥可以操作对应管理资源；仅可交给可信任的后端服务，租户及数据行访问策略由接入系统负责。

### Migration

此功能通过 SQLite／PostgreSQL 数据库迁移新增 `ManagementApiKeys` 管理表。请先完成迁移再签发密钥。已有管理员 JWT 和 MCP 密钥保持不变。

MCP 客户端的连接方式，请参阅 [MCP 客户端接入指南](/zh-hans/docs/mcp/client-onboarding)。
