hs-sql-agent 在 `/mcp` 提供 **Streamable HTTP** MCP 端点。使用内置管理界面时，正常的接入方式不是手动拼 endpoint 和 header，而是在签发密钥后直接复制 hs-sql-agent 生成好的 MCP 客户端配置。

  <DocCard title="确认 DML 支持" icon="FORM" description="只要密钥可以调用 DML，实际部署的 MCP 客户端版本还必须支持 form Elicitation。" />
</CardGrid>

## 推荐接入流程

<Steps>
  <Step title="签发 MCP 密钥">
进入 **Runtime → MCP Keys**，为目标数据库创建密钥，并只开放客户端真正需要的工具和表。
  </Step>
  <Step title="使用一次性的 Save and connect 对话框">
点击 **Issue Key** 成功后，hs-sql-agent 会立即显示明文密钥和生成好的客户端配置。这是管理界面唯一能取得该明文值的时机。
  </Step>
  <Step title="选择 MCP 客户端并复制配置">
切换到 **Claude Desktop**、**Cursor**、**Visual Studio Code** 或 **Generic HTTP** 标签页，再点击对应的 **Copy ... config**。复制出的 JSON 已经包含 MCP endpoint 和 `X-MCP-Server-Key`，不需要手动再拼请求头。
  </Step>
  <Step title="粘贴到客户端并验证">
把复制的 JSON 粘贴进 MCP 客户端配置后连接。如果这把密钥可以执行 DML，生产使用前还要验证 form Elicitation 的拒绝和接受两条流程。
  </Step>
</Steps>

<Callout type="warning" title="关闭对话框前先保存配置">
服务器不会保存 MCP 明文密钥。关闭 **Save and connect** 后，管理界面无法再根据已保存的密钥记录还原同一份明文密钥和配置。**Rotate** 或 **Duplicate** 会创建新的明文密钥并再次打开同一个 onboarding 对话框；**Edit** 不会重新显示已有密钥。
</Callout>

## 生成配置时使用的公开端点

客户端配置中的 URL 来自服务器的公开端点设置：

```json
{
  "Mcp": {
    "PublicEndpoint": "https://sql-agent.example.com/mcp"
  }
}
```

对应的环境变量是 `Mcp__PublicEndpoint`；项目提供的 Compose 配置会把 `MCP_PUBLIC_ENDPOINT` 映射到这个值。

生产环境请在签发正式 MCP 密钥**之前**先把它设置为客户端真正能访问、且包含 `/mcp` 的 URL。管理界面会从 `GET /api/runtime/client-config` 读取该值，并直接放进复制出的配置。

<Callout type="warning" title="不要根据管理界面的 URL 推断 MCP 端点">
管理界面和 MCP 端点可能使用不同的 host、port 或反向代理路径。非 Development 环境要求配置 HTTP 或 HTTPS 绝对 URL。
</Callout>

## 对话框目前会生成什么

Issue、Rotate 或 Duplicate 成功后，当前管理界面提供四种配置：

- **Claude Desktop** — 直接 HTTP 的 `mcpServers` 项；
- **Cursor** — HTTP `mcpServers` 项；
- **Visual Studio Code** — `servers` 项；
- **Generic HTTP** — Streamable HTTP 连接对象。

四种输出都会带入服务器配置的 endpoint 和本次生成的 MCP 密钥。一般不需要手动重建这些 JSON。

## Generic / 手动验证参考

如果某个 MCP 客户端需要不同的外层配置格式，可以使用 Generic HTTP 标签页作为参考。协议层的验证方式是：

```http
X-MCP-Server-Key: <MCP key>
```

## DML 兼容性需要单独确认

成功连接 `/mcp`，**不代表客户端支持 DML 审批**。

`execute_dml_sql` 和已发布的 DML Custom Tools 需要 form Elicitation。生产环境允许 DML 前，请使用实际安装的客户端版本验证以下两种情况：

1. 拒绝 Elicitation 请求，确认数据修改没有提交。
2. 接受 Elicitation 请求，确认只有已批准的数据修改能够完成。

<Callout type="danger" title="不支持 Elicitation，就不能使用 Safe DML">
如果客户端没有声明并实现 form Elicitation，hs-sql-agent 会拒绝 DML 操作。只读客户端应直接从 MCP 密钥的允许工具列表中移除数据修改工具，不要把密钥保留为 unrestricted。
</Callout>
