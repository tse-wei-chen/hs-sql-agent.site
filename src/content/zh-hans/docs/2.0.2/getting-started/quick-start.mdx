<Callout type="info" title="如果不需要嵌入现有宿主应用，建议从 Docker 开始">
Docker Compose 是最短路径，因为仓库已经包含服务连接配置和环境变量映射。NuGet 方式更适合把 hs-sql-agent 嵌入现有 ASP.NET Core 宿主的团队。
</Callout>

## Docker Compose

<Steps>
  <Step title="创建环境配置文件" description="复制仓库中的示例文件，让配置保持明确并便于审查。">

```bash
cp .env.example .env
```

  </Step>
  <Step title="替换签名密钥" description="为 HMAC_KEY 和 JWT_KEY 分别设置不同且至少 32 字节的唯一密钥。">
`.env.example` 中的值只是占位示例，请勿原样部署到生产环境。
  </Step>
  <Step title="启动服务" description="启动默认的单实例服务栈。">

```bash
docker compose up -d
```

  </Step>
  <Step title="打开管理界面" description="应用默认监听 8080 端口。">
本地环境可以打开 `http://localhost:8080`，然后完成首个管理员设置。
  </Step>
</Steps>

## 签发第一把 MCP 密钥

<Steps>
  <Step title="打开 Runtime → MCP Keys" description="MCP 密钥是客户端身份识别和授权检查的边界。" />
  <Step title="选择数据库和工具权限范围" description="把密钥绑定到一个 Database Management 条目，并且只开放客户端实际需要的工具。" />
  <Step title="复制明文密钥" description="密钥签发后会在生命周期对话框中显示一次，请复制并保存到客户端的安全凭据存储中。" />
  <Step title="使用自动生成的客户端配置" description="也可以通过 X-MCP-Server-Key 请求头把密钥发送到 Streamable HTTP 端点。" />
</Steps>

默认 MCP 端点是 `/mcp`。如果客户端不在本机，请把 `MCP_PUBLIC_ENDPOINT` 设置为外部可以访问的 HTTP 或 HTTPS 绝对 URL，并包含 `/mcp` 路径。

<Callout type="warning" title="DML 需要客户端支持 MCP Elicitation">
不要因为客户端能够调用 MCP 工具就直接启用 `execute_dml_sql`。为了让用户能够查看并批准实际修改内容，客户端还必须支持 MCP form Elicitation。
</Callout>
