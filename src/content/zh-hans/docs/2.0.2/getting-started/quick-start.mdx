<Callout type="info" title="除非你已经有 host application，否则建议从 Docker 开始">
Docker Compose 是最短路径，因为 repository 已包含 service wiring 与 environment-variable mapping。NuGet 路径适合需要把 hs-sql-agent 嵌入现有 ASP.NET Core host 的团队。
</Callout>

## Docker Compose

<Steps>
  <Step title="建立环境文件" description="复制 repository 内的范例，让 configuration 保持明确且可审查。">

```bash
cp .env.example .env
```

  </Step>
  <Step title="替换签名 secrets" description="将 HMAC_KEY 与 JWT_KEY 设为两个不同、唯一且至少 32 bytes 的 secrets。">
`.env.example` 中的值只是 placeholder。不要原样部署。
  </Step>
  <Step title="启动服务" description="启动默认的 single-instance stack。">

```bash
docker compose up -d
```

  </Step>
  <Step title="打开 Admin Panel" description="默认 application listener 使用 port 8080。">
本机环境可打开 `http://localhost:8080`，完成第一位 administrator 的设置。
  </Step>
</Steps>

## 签发第一把 MCP key

<Steps>
  <Step title="打开 Runtime → MCP Keys" description="Key 是 MCP identity 与 authorization boundary。" />
  <Step title="选择 database 与 tool scope" description="将 key 绑定到一个 Database Management entry，并只开放 client 所需的 tools。" />
  <Step title="复制 plaintext key" description="Lifecycle dialog 会显示新签发的 secret 供你复制；请将它保存到 client secret store。" />
  <Step title="使用生成的 client configuration" description="也可以把 secret 作为 X-MCP-Server-Key 发送到 Streamable HTTP endpoint。" />
</Steps>

默认 MCP endpoint 是 `/mcp`。如果 client 位于本机之外，请将 `MCP_PUBLIC_ENDPOINT` 设置为外部可访问的绝对 HTTP 或 HTTPS URL，并包含 `/mcp`。

<Callout type="warning" title="DML 需要 client 支持 Elicitation">
不要仅因为 client 能调用 MCP tools 就启用 `execute_dml_sql`。Client 还必须兼容 MCP form Elicitation，才能让人工操作员审查并批准具体 mutation impact。
</Callout>
