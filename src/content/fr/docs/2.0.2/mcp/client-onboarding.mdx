## Connecter un client

<Steps>
  <Step title="Créer une clé MCP">
Dans le panneau d’administration, créez une clé associée à la base de données voulue. Si le client n’a pas besoin d’un accès complet, limitez les outils et les tables qu’il peut utiliser.
  </Step>
  <Step title="Utiliser le point de terminaison MCP public">
L’adresse doit être accessible par le client. Ne supposez pas que l’interface d’administration et le point de terminaison MCP utilisent la même origine.
  </Step>
  <Step title="Authentifier chaque requête">
Envoyez la clé dans l’en-tête MCP indiqué ci-dessous. Traitez la clé en clair comme un secret : une fois la boîte de dialogue de cycle de vie fermée, le serveur n’affichera plus cette même valeur.
  </Step>
  <Step title="Vérifier le client réellement installé">
Commencez par confirmer la découverte du schéma et l’exécution des requêtes. Si DML doit être activé, testez séparément le comportement d’Elicitation par formulaire avant le passage en production.
  </Step>
</Steps>

```http
X-MCP-Server-Key: <MCP key>
```

## Point de terminaison public

L’URL affichée aux opérateurs et utilisée dans les configurations client générées provient du paramètre serveur suivant :

```json
{
  "Mcp": {
    "PublicEndpoint": "https://sql-agent.example.com/mcp"
  }
}
```

La variable d’environnement équivalente est `Mcp__PublicEndpoint`. La configuration Compose fournie transmet `MCP_PUBLIC_ENDPOINT` vers ce paramètre.

<Callout type="warning" title="Ne déduisez pas l’adresse MCP à partir de l’URL de l’interface d’administration">
L’interface d’administration et le point de terminaison MCP peuvent utiliser des hôtes, ports ou chemins de proxy inverse différents. Hors environnement Development, le serveur exige une URL publique HTTP ou HTTPS absolue. Configurez l’adresse que le client MCP peut réellement joindre.
</Callout>

## Configuration client générée

Après la création, la rotation ou la duplication d’une clé MCP, le panneau d’administration peut générer directement une configuration HTTP pour Claude Desktop, Cursor et les clients Streamable HTTP génériques.

La clé en clair n’est affichée que temporairement. Une fois la boîte de dialogue de cycle de vie fermée, le serveur ne peut plus afficher à nouveau cette même valeur secrète.

## La compatibilité DML doit être vérifiée séparément

Le fait qu’un client se connecte correctement à `/mcp` **ne prouve pas qu’il sait gérer l’approbation DML**.

`execute_dml_sql` et les DML Custom Tools publiés exigent la prise en charge de l’Elicitation par formulaire. Avant d’autoriser DML en production, testez la version exacte du client installée et vérifiez les deux scénarios :

1. Refuser une demande d’Elicitation et confirmer qu’aucune modification n’est validée.
2. Accepter une demande d’Elicitation et confirmer que seule la modification approuvée aboutit.

<Callout type="danger" title="Sans Elicitation, pas de DML gouverné">
Si un client ne déclare pas et n’implémente pas l’Elicitation par formulaire, hs-sql-agent refuse l’opération DML. Pour les clients en lecture seule, préférez une clé MCP dont la liste d’outils autorisés exclut les outils de modification plutôt que de laisser la clé sans restriction.
</Callout>
