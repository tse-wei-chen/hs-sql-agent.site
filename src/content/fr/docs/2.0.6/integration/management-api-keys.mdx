Une **clé d’API d’administration** permet à un service backend ou à un outil de déploiement de gérer les Custom Tools, de modifier la configuration et d’émettre des identifiants d’accès. Chaque clé n’autorise que les opérations que vous avez sélectionnées.

## Créer une clé

1. Connectez-vous avec `/runtime/security.edit` et ouvrez **Runtime → Management API Keys**.
2. Indiquez un nom et une date d’expiration (365 jours au maximum).
3. Sélectionnez uniquement les autorisations nécessaires.
4. Émettez la clé et copiez immédiatement son secret, affiché une seule fois.

Stockez la clé dans le gestionnaire de secrets du backend, jamais dans le code frontend ou un dépôt.

## Appeler l’API d’administration

Transmettez le secret dans l’en-tête HTTP `X-API-Key` :

```bash
curl "https://agent.example.com/api/CustomSqlTool" \
  -H "X-API-Key: ${HS_MANAGEMENT_API_KEY}"
```

N’envoyez pas simultanément les en-têtes `X-API-Key` et `Authorization` : la requête serait refusée.

## Opérations courantes et autorisations

Les intégrations utilisent directement les points d’accès `/api` existants et leurs autorisations canoniques, sans API spécifique supplémentaire.

| Opération | API | Canonical Permission |
| --- | --- | --- |
| Lister les Custom Tools | `GET /api/CustomSqlTool` | `/runtime/custom-tools.view` |
| Créer un Custom Tool | `POST /api/CustomSqlTool` | `/runtime/custom-tools.create` |
| Publier un Custom Tool | `POST /api/CustomSqlTool/{id}/publish` | `/runtime/custom-tools.edit` |
| Lister les clés d’accès | `GET /api/runtime/mcp-keys` | `/runtime/mcp-keys.view` |
| Émettre une clé d’accès | `POST /api/runtime/mcp-keys` | `/runtime/mcp-keys.create` |

## Autorisations et gestion des clés

Appliquez le principe du moindre privilège. Un administrateur peut révoquer une clé à tout moment ou la renouveler : une nouvelle clé est alors émise et l’ancienne est immédiatement invalidée. L’Admin Store ne conserve que le hachage du secret ; les opérations sont consignées sous l’identité `management-api-key`.

L’émission, la rotation et la révocation d’une clé d’administration nécessitent une session administrateur disposant de `/runtime/security.edit`.

> Les autorisations de gestion ne sont pas automatiquement limitées à une base de données ou à un locataire. Conservez la clé dans un backend de confiance et appliquez les règles d’accès métier côté intégration.

## Prérequis de déploiement

Avant l’émission des clés, appliquez la migration SQLite ou PostgreSQL de l’Admin Store afin de créer la table `ManagementApiKeys`.
