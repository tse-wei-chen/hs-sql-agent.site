需要從 SaaS 後端、排程或部署流程自動建立 Custom Tools、更新設定或簽發存取憑證時，可以使用**管理 API 金鑰**。每把金鑰只會取得管理員明確授予的 API 權限。

## 建立金鑰

以具有 `/runtime/security.edit` 權限的管理員登入，前往 **Runtime → Management API Keys**。

1. 輸入金鑰名稱，例如 `production-integration`。
2. 設定到期時間（最長 365 天）。
3. 勾選整合服務需要的管理權限。
4. 建立後立即複製明文金鑰；金鑰只會顯示一次。

請將金鑰存放在後端的機密管理服務，不要放在瀏覽器前端或版本庫。

## 呼叫管理 API

將金鑰放在 `X-API-Key` HTTP 標頭，即可呼叫具有權限的既有管理 API：

```bash
curl "https://agent.example.com/api/CustomSqlTool" \
  -H "X-API-Key: ${HS_MANAGEMENT_API_KEY}"
```

使用 `X-API-Key` 時，不要同時送出 `Authorization` 標頭，否則請求會被拒絕。

## 常見操作與所需權限

| 操作 | API | Canonical Permission |
| --- | --- | --- |
| 列出 Custom Tools | `GET /api/CustomSqlTool` | `/runtime/custom-tools.view` |
| 建立 Custom Tool | `POST /api/CustomSqlTool` | `/runtime/custom-tools.create` |
| 發布 Custom Tool | `POST /api/CustomSqlTool/{id}/publish` | `/runtime/custom-tools.edit` |
| 列出已發行的存取金鑰 | `GET /api/runtime/mcp-keys` | `/runtime/mcp-keys.view` |
| 簽發存取金鑰 | `POST /api/runtime/mcp-keys` | `/runtime/mcp-keys.create` |

所有請求仍會經過原本的管理 API 權限驗證，不需要建立額外的 SaaS 專用 API。

## 權限與金鑰管理

- **最小權限**：只勾選整合需要的 Canonical Permissions。
- **撤銷**：管理員可隨時撤銷金鑰，後續請求會立即失效。
- **輪替**：會簽發新金鑰並立即撤銷舊金鑰。
- **稽核**：金鑰明文不會寫入資料庫；管理操作會以 `management-api-key` 身分記錄。

管理 API 金鑰的建立、輪替與撤銷，須由具有 `/runtime/security.edit` 權限的登入管理員操作。

> 目前金鑰的權限範圍是**管理 API 操作**，不會自動依特定資料庫 ID 或租戶限制。請只交給可信任的後端服務，並由整合方負責業務資料授權。

## 部署需求

正式使用前，請完成 Admin Store 的 SQLite 或 PostgreSQL migration，以建立 `ManagementApiKeys` 資料表。

各欄位的 Request／Response 定義、HTTP 狀態碼與完整範例，請參閱[管理 REST API 串接規格](/zh-hant/docs/2.0.6/reference/admin-api-contracts)。
