本頁記錄 **hs-sql-agent 2.0.1 原始碼中實際存在的 controller routes**；內建管理介面使用的就是這些端點。

<Callout type="warning" title="這是 2.0.1 原始碼契約，不是獨立版本化的 REST 標準">
2.0.1 沒有把這些 controllers 放進 `/v1` 相容命名空間。若有內建管理介面以外的整合直接呼叫這些端點，應固定 hs-sql-agent 版本，並在升級時重新檢查這份參考。
</Callout>

## 身分驗證與授權

大部分管理端路由都需要已完成驗證的管理員身分；受保護的執行階段操作還會檢查 path/action 權限，例如 `/runtime/db-management` → `view`、`/auth/role` → `edit`。

首次設定、登入、註冊，以及部分 OIDC、密碼復原、MFA challenge completion 等必須在工作階段建立前開始的流程，則有匿名存取例外。

請見 [權限](/zh-hant/docs/administration/permissions)。

## Credential status

2.0.1 提供 `GET /api/Credential/status`，只回傳簡單的 Credential API 運作狀態；controller 本身沒有 `[Authorize]` attribute。應把它視為用途有限的狀態端點，而不是經驗證的憑證管理 API。

## 錯誤與相容性

Controllers 使用一般 HTTP status code，例如驗證錯誤 400、身分驗證 / 授權錯誤 401 / 403、找不到資源 404、衝突 409、稽核匯出過大 413，以及部分受限制 SQL 壓力路徑的 429。

若外部自動化直接依賴這套 API，請固定使用 2.0.1，並驗證實際使用的 response model。本文件刻意記錄路由與重要契約，不把所有管理端 view model 宣稱成永久、版本化的外部 SDK。
