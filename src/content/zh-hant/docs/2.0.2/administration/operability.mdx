運作狀態頁用來了解**受治理的執行階段目前是否正常運作**。稽核著重單一安全或執行事件；OpenTelemetry 與 Prometheus 則把遙測資料送到外部監控系統。

## 執行指標

指標端點可以回報：

- Query / DML 執行次數；
- 成功 / 失敗次數與成功率；
- p50 / p95 延遲；
- 延遲樣本數，以及是否採用取樣；
- 慢查詢次數；
- IP 速率限制次數；
- MCP 金鑰速率限制次數。

可依時間範圍、資料庫、access key、工具名稱縮小查詢範圍。

<Callout type="info" title="取樣延遲應按照取樣資料解讀">
回應會明確提供樣本數，以及延遲是否經過取樣。當執行階段回報使用 sampling 時，不要把 p50 / p95 當成完整的延遲分布。
</Callout>

## 資料庫健康狀態

每筆資料庫健康紀錄會顯示受管理連線目前的運作狀態：

| 欄位 | 意義 |
| --- | --- |
| `Status` | 目前健康狀態 |
| `LastCheckedAt` | 最近一次探測時間 |
| `LastSuccessAt` | 最近一次成功探測時間 |
| `LatencyMs` | 有資料時的探測延遲 |
| `ConsecutiveFailures` | 目前連續失敗次數 |
| `OutageStartedAt` | 已知時的目前故障開始時間 |
| `LastError` | 最近一次資料庫或探測錯誤 |

健康探測由 `HEALTH_PROBE_*` 設定控制。如果背景探測關閉，就不能把這個頁面當成持續更新的外部監控系統。

## MCP 金鑰使用情形

金鑰使用資料會回報金鑰識別資訊與名稱、最後使用時間、請求數、成功 / 失敗次數、速率限制次數與拒絕率。

這些資訊適合用來找出長期未使用的憑證、異常高流量的 Agent，或持續撞到限制的金鑰。要調整權限範圍或限制前，請先閱讀 [MCP 金鑰](/zh-hant/docs/administration/mcp-keys)。

## 外送紀錄

執行階段會保存已設定的告警、SIEM webhook 等外送嘗試。每筆紀錄包含：

- 類別與狀態；
- 嘗試次數；
- 建立、送達與最後嘗試時間；
- 最新錯誤。

清單端點的 `limit` 預設為 `100`。

## 重試外送

| 操作 | 權限 |
| --- | --- |
| 指標 / 資料庫健康 / 金鑰使用 / 外送清單 | `/runtime/operability` → `view` |
| 重試外送 | `/runtime/operability` → `edit` |

重試屬於明確的管理操作。修正暫時性的網路或目的端問題後可以使用，但反覆重試不能取代修正錯誤的 endpoint、secret 或下游服務。

<Callout type="warning" title="重試可能再次送出同一事件">
執行前先確認目的端可以接受重複或延遲送達的事件，也要排除「遠端其實已成功，但本機狀態沒有如預期更新」的情況。
</Callout>
