<Callout type="info" title="如果不需要嵌入既有主機應用程式，建議從 Docker 開始">
Docker Compose 是最短路徑，因為儲存庫已經包含服務連接設定與環境變數對應。NuGet 方式適合要把 hs-sql-agent 嵌入既有 ASP.NET Core 主機的團隊。
</Callout>

## Docker Compose

<Steps>
  <Step title="建立環境設定檔" description="複製儲存庫中的範例檔，讓設定保持明確並方便審查。">

```bash
cp .env.example .env
```

  </Step>
  <Step title="更換簽章密鑰" description="HMAC_KEY 與 JWT_KEY 請分別使用不同、至少 32 位元組的唯一密鑰。">
`.env.example` 中的值只是範例，請勿原樣部署到正式環境。
  </Step>
  <Step title="啟動服務" description="啟動預設的單一執行個體服務。">

```bash
docker compose up -d
```

  </Step>
  <Step title="開啟管理介面" description="應用程式預設監聽 8080 連接埠。">
本機環境可開啟 `http://localhost:8080`，然後完成第一個管理員設定。
  </Step>
</Steps>

## 發行第一把 MCP 金鑰

<Steps>
  <Step title="開啟 Runtime → MCP Keys" description="MCP 金鑰是用戶端身分與授權檢查的邊界。" />
  <Step title="選擇資料庫與工具權限範圍" description="把金鑰綁定到一個 Database Management 項目，並且只開放用戶端實際需要的工具。" />
  <Step title="複製明文金鑰" description="金鑰發行後會在生命週期對話框中顯示一次，請複製並保存到用戶端的安全憑證儲存位置。" />
  <Step title="使用自動產生的用戶端設定" description="也可以透過 X-MCP-Server-Key 要求標頭，把密鑰傳送到 Streamable HTTP 端點。" />
</Steps>

預設 MCP 端點是 `/mcp`。如果用戶端不在本機，請把 `MCP_PUBLIC_ENDPOINT` 設為外部可存取的 HTTP 或 HTTPS 絕對 URL，並包含 `/mcp` 路徑。

<Callout type="warning" title="DML 需要用戶端支援 MCP Elicitation">
不要只因為用戶端能呼叫 MCP 工具就直接啟用 `execute_dml_sql`。為了讓使用者能查看並核准實際修改內容，用戶端還必須支援 MCP form Elicitation。
</Callout>
