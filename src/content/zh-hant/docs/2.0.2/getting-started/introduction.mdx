hs-sql-agent 是一個提供**受治理 SQL 存取**的 HTTP MCP Server。它可以連接 PostgreSQL、MySQL、SQL Server、Oracle、SQLite 與 Firebird，同時把 authentication、access policy、SQL validation 與 mutation approval 留在 server side。

<Flow items={["MCP client", "MCP key scope", "SQL compiler", "Policy & capability checks", "Database"]} />

<Callout type="danger" title="不要讓 LLM 成為資料庫的安全邊界">
AI 產生的 SQL 是不可信輸入。Model 可以提出 SQL，但真正決定 request 是否被授權、語意是否受支援、是否能安全執行的是 server。
</Callout>

## Server 負責哪些邊界？

<CardGrid columns={2}>
  <DocCard title="Identity & scope" icon="KEY" description="把 client 綁定到 managed database，並限制 allowed tools、tables 與 runtime limits。" />
  <DocCard title="SQL semantics" icon="AST" description="將支援的 SQL parse 成 structured definitions，驗證 source semantics、證明 target capability，再 compile provider-specific SQL。" />
  <DocCard title="Mutation approval" icon="DML" description="把 write operation 當成獨立 risk class，經過 preview、one-time approval、revalidation 與 exact commit。" />
  <DocCard title="Operations & audit" icon="OPS" description="Rate/concurrency control、audit records、health、telemetry 與 outbound operational delivery 都留在 model 外。" />

## Compiler boundary

Generated SQL 會先被 parse 與 validate。hs-sql-agent 會確認維持 statement 語意所需的 capabilities，只有 request 通過 source、target 與 policy boundaries 後，才會產生 provider-specific SQL。

不支援的 syntax 或 semantics 會被拒絕，而不是偷偷改寫成「看起來差不多」的 SQL。

<Callout type="info" title="支援六種 provider 不代表 arbitrary vendor SQL passthrough">
Provider support 是 capability-driven。某個 construct 必須能被表示、驗證，並依 source/target contract 安全 render。請以 SQL Support Reference 為準，不要假設所有 vendor extension 都會被接受。
</Callout>
