程式庫中的 **v2.0.2 `.env.example`** 是預設 Compose 部署方式的環境變數清單。本頁以該檔案的變數名稱為基準；如果範例註解和 v2.0.2 執行階段驗證邏輯不一致，則以實際可執行的程式碼為準。

<Callout type="warning" title="正式環境啟動前請先產生真正的密鑰">
`HMAC_KEY` 與 `JWT_KEY` 都必須至少 32 bytes，而且應使用彼此獨立的值。程式庫中的字串只是 placeholder。若啟用 webhook URL，對應的 webhook secret 也必須至少 32 bytes。
</Callout>

## 應用程式與控制平面

| 變數 | `.env.example` 範例 / 預設 | 用途 |
| --- | --- | --- |
| `ASPNETCORE_URLS` | `http://+:8080` | ASP.NET Core 主要監聽位址 |
| `ALLOWED_HOSTS` | `*` | ASP.NET Core host filtering |
| `ADMIN_DATABASE_PROVIDER` | `Sqlite` | 管理端 / 控制平面資料庫 provider |
| `ADMIN_DATABASE_CONNECTION_STRING` | `Data Source=/app/data/hsqlagent.db` | 儲存帳號、角色、金鑰、稽核紀錄、政策與其他控制平面狀態 |
| `HMAC_KEY` | placeholder | 保護並驗證已簽發 MCP 金鑰的 HMAC secret；至少 32 bytes |
| `MCP_PUBLIC_ENDPOINT` | `http://localhost:8080/mcp` | 產生 MCP 用戶端設定時使用的絕對端點 URL |

`MCP_PUBLIC_ENDPOINT` 必須是 HTTP / HTTPS 絕對 URL。正式環境應填入**用戶端真正能連線**的 URL，並包含 `/mcp`；不要填只有 container 內部網路才能解析的位址。

### 管理資料庫拓樸

單一執行個體範例使用 SQLite；分散式範例使用 PostgreSQL：

```text
ADMIN_DATABASE_PROVIDER=Postgres
ADMIN_DATABASE_CONNECTION_STRING=Host=postgres;Port=5432;Database=hsqlagent;Username=postgres;Password=...
```

當多個 hs-sql-agent 執行個體必須共用身分、金鑰、政策、稽核與其他控制平面紀錄時，應使用共用的管理資料庫。

## 快取

| 變數 | 單一執行個體 | 分散式 | 用途 |
| --- | --- | --- | --- |
| `CACHE_PROVIDER` | `Memory` | `Redis` | 執行階段快取 provider |
| `CACHE_CONNECTION_STRING` | empty | `redis:6379` | 選擇 Redis 時使用的連線字串 |
| `CACHE_KEY_PREFIX` | `hsqlagent:cache:` | 相同 | 快取 key namespace |

只有在快取狀態不需要跨應用程式執行個體共用時，程序內的 `Memory` provider 才適合。

## Bootstrap / 自動佈建

| 變數 | 範例 | 用途 |
| --- | --- | --- |
| `BOOTSTRAP_ENABLED` | `false` | 啟用啟動時的佈建與同步 |
| `BOOTSTRAP_DB_ID` | `default-db` | 初始資料庫的穩定 bootstrap 識別字 |
| `BOOTSTRAP_DB_NAME` | `Default DB` | 管理介面顯示的資料庫名稱 |
| `BOOTSTRAP_DB_PROVIDER` | empty | 要佈建的資料庫 provider |
| `BOOTSTRAP_DB_HOST` | `localhost` | 資料庫主機 |
| `BOOTSTRAP_DB_PORT` | `5432` | 資料庫連接埠 |
| `BOOTSTRAP_DB_DATABASE` | `mydb` | database / catalog / file 值 |
| `BOOTSTRAP_DB_USERNAME` | `myuser` | 資料庫使用者名稱 |
| `BOOTSTRAP_DB_PASSWORD` | `mypassword` | 資料庫密碼 |
| `BOOTSTRAP_DB_EXTRA_SETTINGS` | empty | provider 專用的額外連線設定 |
| `BOOTSTRAP_MCP_KEY_ID` | `default-key` | 初始 MCP 金鑰的穩定 bootstrap 識別字 |
| `BOOTSTRAP_MCP_KEY_NAME` | `Default MCP Key` | 管理介面顯示的金鑰名稱 |
| `BOOTSTRAP_MCP_KEY` | placeholder | 初始原始金鑰值 |
| `BOOTSTRAP_MCP_ALLOWED_TOOLS` | empty | Bootstrap 金鑰的工具限制 |

由 bootstrap 管理的 MCP 金鑰不走一般金鑰生命週期，不能透過正常管理介面編輯、輪替或撤銷。需要修改時，應變更它的來源設定。

## 管理端身分驗證

| 變數 | 範例 | 用途 |
| --- | --- | --- |
| `JWT_KEY` | placeholder | JWT 簽章密鑰；至少 32 bytes |
| `JWT_ISS` | `HS-Agent` | JWT issuer |
| `JWT_AUD` | `HS-Agent-Users` | JWT audience |
| `JWT_ACCESS_TOKEN_EXPIRATION_MINUTES` | `10` | Access token 有效時間 |
| `JWT_REFRESH_TOKEN_EXPIRATION_DAYS` | `1` | Refresh token 有效天數 |
| `AUTH_LOCKOUT_THRESHOLD` | `5` | 暫時鎖定前允許的登入失敗次數；小於 1 時會視為 1 |
| `AUTH_LOCKOUT_MINUTES` | `15` | 暫時鎖定時間 |

這組設定管理的是**管理端身分驗證**，不是 MCP 金鑰驗證。

| --- | --- | --- |
| `OIDC_ENABLED` | `false` | 啟用 OIDC 身分驗證 |
| `OIDC_AUTHORITY` | empty | Identity provider authority |
| `OIDC_CLIENT_ID` | empty | OIDC client ID |

| `OIDC_REQUIRE_HTTPS_METADATA` | `true` | 要求使用 HTTPS discovery metadata |

| `OIDC_NAME_CLAIM` | `name` | Display name claim |

| `OIDC_EMAIL_VERIFIED_CLAIM` | `email_verified` | Email 驗證狀態 claim |

| `OIDC_SCOPE_0..2` | `openid`, `profile`, `email` | 預設 scopes |
| `OIDC_ROLE_MAPPING_SQL_ADMINS` | `SuperUser` | 外部角色 → 本機角色映射範例 |
| `OIDC_AUTO_PROVISION` | `true` | 外部身分成功解析後自動建立使用者 |
| `OIDC_FRONTEND_CALLBACK_URL` | `/sso-callback` | 前端完成登入的 callback route |
| `OIDC_LOGIN_CODE_EXPIRATION_MINUTES` | `2` | 短效登入 code 的有效時間 |
| `OIDC_TOTP_ISSUER` | `HS SQL Agent` | TOTP issuer 標籤 |
| `DATA_PROTECTION_KEY_PATH` | `/app/data/data-protection-keys` | 持久保存 ASP.NET Core data-protection keys 的目錄 |

<Callout type="danger" title="使用受保護的身分狀態時，必須持久化 data-protection keys">
如果重新啟動後 data-protection key ring 消失，受保護的 MFA secrets 與外部登入狀態可能無法再次解密。正式環境請把 `DATA_PROTECTION_KEY_PATH` 掛載到持久儲存空間。
</Callout>

請參考 [OIDC 與 MFA](/zh-hant/docs/security/oidc-mfa)。

## 健康檢查、慢查詢、外送與稽核保留

| 變數 | 範例 | 用途 |
| --- | --- | --- |
| `HEALTH_PROBE_ENABLED` | `false` | 啟用背景資料庫健康探測 |
| `HEALTH_PROBE_INTERVAL_SECONDS` | `60` | 探測間隔 |
| `HEALTH_PROBE_TIMEOUT_SECONDS` | `10` | 單次探測逾時 |
| `HEALTH_PROBE_MAX_CONCURRENCY` | `4` | 限制同時進行的探測工作數 |
| `SLOW_QUERY_THRESHOLD_MS` | `1000` | 執行時間大於等於此值的查詢會記錄為慢查詢 |
| `ALERT_WEBHOOK_URL` | empty | 選用的帶簽章告警目的地 |
| `ALERT_WEBHOOK_SECRET` | empty | HMAC / signing secret；啟用 URL 時至少 32 bytes |
| `SIEM_WEBHOOK_URL` | empty | 選用的帶簽章 SIEM 目的地 |
| `SIEM_WEBHOOK_SECRET` | empty | HMAC / signing secret；啟用 URL 時至少 32 bytes |
| `DELIVERY_MAX_ATTEMPTS` | `6` | 外送最多嘗試次數 |
| `DELIVERY_MAX_CONCURRENCY` | `4` | 限制同時進行的外送數 |
| `AUDIT_RETENTION_DAYS` | `90` | 保留天數；`0` 代表停用自動保留處理 |
| `AUDIT_RETENTION_MODE` | `Archive` | **執行階段合法值：`Archive` 或 `Purge`** |
| `AUDIT_ARCHIVE_PATH` | `/app/data/audit-archive` | `Archive` 模式的封存目的地 |
| `AUDIT_FALLBACK_PATH` | `/app/data/audit-fallback.jsonl` | 稽核備援路徑；啟動驗證要求有設定 |
| `AUDIT_RETENTION_RUN_HOUR_UTC` | `2` | 排程執行的 UTC 小時；執行階段會限制在 0–23 |

<Callout type="warning" title="v2.0.2 範例註解提到 Delete，但執行階段使用 Purge">
`AuditRetentionService` 只接受 `Archive` 與 `Purge`。其他非 Archive 值（包含 `Delete`）會觸發 `AuditRetentionMode must be Purge or Archive.`。本參考頁以實際可執行的 v2.0.2 程式碼為準，不採用已過時的範例註解。
</Callout>

`Archive` 會先把過期稽核資料列寫入 JSONL 封存檔，再從管理資料庫刪除；`Purge` 則直接刪除符合保留條件的紀錄，不建立封存檔。

| 變數 | 範例 | 用途 |

## Docker 環境變數與內嵌 .NET capability options

Docker / ToolBox 環境變數代表完整的獨立伺服器設定介面。新的 NuGet 整合方式不同：`AddHsSqlAgentCore()` 本身沒有 options，每個被啟用的 capability 只擁有自己的設定。

例如：

- `HsSqlAgentAdminStoreOptions`：管理資料庫 provider 與 connection string；
- `HsSqlAgentRuntimeOptions`：cache、rate limiting、synchronization、SQL concurrency、DML approval storage、bootstrap、operability；
- `HsSqlAgentBuiltInAuthOptions`：JWT、password reset/SMTP、enterprise identity/OIDC；
- `McpOptions`：公開 MCP endpoint 與 HMAC secret；
- `TelemetryOptions`：Prometheus 與 OTLP settings。

`HsSqlAgentServiceOptions` 只保留作為舊版整合 API 的相容 DTO。沒有啟用的 capability 不會建立或驗證它的 options，因此使用 `AddHsSqlAgentHostAuthorization(...)` 的內嵌 host 不需要設定 HsSqlAgent JWT、SMTP、password-reset 或 OIDC。

模組化 API 保留原有程式預設值；`.env.example` 仍是獨立 ToolBox 部署的範例，不代表每個內嵌 host 都必須設定所有 capability。

請參考 [ASP.NET Core 整合](/zh-hant/docs/integration/aspnet-core)。
