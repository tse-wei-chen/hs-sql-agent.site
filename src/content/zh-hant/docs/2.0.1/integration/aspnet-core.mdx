`HsSqlAgent.Server` 可以直接 host 在既有 ASP.NET Core application，不一定只能使用 repository 的 standalone service。

<CardGrid columns={3}>
  <DocCard title="Package" icon="PKG" description="把 HsSqlAgent.Server 安裝進既有 ASP.NET Core host。" />
  <DocCard title="API / MCP only" icon="API" description="若 host 只需要 hs-sql-agent API/MCP pipeline、不需要 packaged Admin UI，就使用 UseHsSqlAgent()。" />
  <DocCard title="Embedded Admin UI" icon="UI" description="若同一個 host 也要提供 packaged operator interface，再 chain .ServeAdminUi()。" />
</CardGrid>

## Minimal setup

<Steps>
  <Step title="安裝 package">

```bash
dotnet add package HsSqlAgent.Server
```

  </Step>
  <Step title="註冊 hs-sql-agent services">

```csharp
builder.Services.AddHsSqlAgent(options =>
{
    // Configure service options here.
});
```

  </Step>
  <Step title="Map API/MCP pipeline">

```csharp
app.UseHsSqlAgent();
```

`UseHsSqlAgent()` 會 expose hs-sql-agent API/MCP pipeline，不要求 packaged Admin UI 一定存在。
  </Step>
  <Step title="視需要提供 Admin UI">

```csharp
app.UseHsSqlAgent().ServeAdminUi();
```

當 application 同時要提供 runtime endpoints 與 packaged Admin UI 時使用這個形式。
  </Step>
</Steps>

## Pipeline defaults

| Surface | Default |
| --- | --- |
| MCP endpoint | `/mcp` |
| Admin API prefix | `/api` |
| Admin UI request path | `/` |
| Admin UI content root | `wwwroot` |

Service options 涵蓋 MCP public endpoint、bootstrap settings、enterprise identity、operability、telemetry、admin database、authentication、rate limiting、distributed synchronization、SQL concurrency、DML approval storage 與 cache configuration。

<Callout type="warning" title="Embed package 不會讓 security boundary 變鬆">
它仍然是與 standalone server 相同的 governed runtime。Host 仍需要 unique HMAC/JWT secrets、正確 externally reachable MCP public endpoint、需要時持久化 data-protection keys，並依 deployment topology 選擇合適的 database/cache/distributed providers。
</Callout>
