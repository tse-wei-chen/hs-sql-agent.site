<Callout type="info" title="既存のホストアプリケーションへ組み込む必要がなければ Docker から始めてください">
Docker Compose が最短です。リポジトリにサービス構成と環境変数の対応付けが用意されています。NuGet は、既存の ASP.NET Core ホストへ hs-sql-agent を組み込みたい場合に使用します。
</Callout>

## Docker Compose

<Steps>
  <Step title="環境設定ファイルを作成" description="管理しやすいよう、リポジトリに含まれるサンプルをコピーして明示的に設定します。">

```bash
cp .env.example .env
```

  </Step>
  <Step title="署名用シークレットを変更" description="HMAC_KEY と JWT_KEY には、それぞれ異なる 32 バイト以上の値を設定します。">
`.env.example` の値はサンプルです。そのまま本番環境へ配置しないでください。
  </Step>
  <Step title="サービスを起動" description="標準の単一インスタンス構成を起動します。">

```bash
docker compose up -d
```

  </Step>
  <Step title="管理画面を開く" description="標準ではポート 8080 で待ち受けます。">
ローカル環境では `http://localhost:8080` を開き、最初の管理者設定を完了します。
  </Step>
</Steps>

## 最初の MCP キーを発行

<Steps>
  <Step title="Runtime → MCP Keys を開く" description="MCP キーはクライアントの識別と認可の境界になります。" />
  <Step title="データベースとツールの権限範囲を選ぶ" description="キーを 1 つの Database Management 設定へ結び付け、クライアントが必要とするツールだけを公開します。" />
  <Step title="平文のキーをコピー" description="発行直後のダイアログに表示されるシークレットをコピーし、クライアント側の安全な保管場所へ保存します。" />
  <Step title="生成されたクライアント設定を使う" description="または Streamable HTTP エンドポイントへの要求に X-MCP-Server-Key ヘッダーを付けます。" />
</Steps>

標準の MCP エンドポイントは `/mcp` です。別の端末から接続する場合は、`MCP_PUBLIC_ENDPOINT` に外部から到達できる HTTP または HTTPS の絶対 URL を `/mcp` まで含めて設定してください。

<Callout type="warning" title="DML には MCP Elicitation への対応が必要です">
MCP ツールを呼び出せるという理由だけで `execute_dml_sql` を有効にしないでください。DML では、人が実際の変更内容を確認して承認できるよう、クライアント側も MCP の form Elicitation に対応している必要があります。
</Callout>
