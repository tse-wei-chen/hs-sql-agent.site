バックエンドサービスやデプロイ処理から Custom Tools の管理、設定変更、アクセス用の認証情報の発行を自動化する場合は、**管理 API キー**を利用できます。キーには選択した管理権限だけが付与されます。

## キーを発行する

1. `/runtime/security.edit` 権限を持つ管理者でログインし、**Runtime → Management API Keys** を開きます。
2. 連携名と有効期限（最大365日）を入力します。
3. 必要な管理権限を選択します。
4. キーを発行し、一度だけ表示される秘密値をコピーします。

秘密値はバックエンドのシークレット管理サービスに保管し、フロントエンドやリポジトリに含めないでください。

## 管理 API を呼び出す

API リクエストの `X-API-Key` ヘッダーに秘密値を指定します。

```bash
curl "https://agent.example.com/api/CustomSqlTool" \
  -H "X-API-Key: ${HS_MANAGEMENT_API_KEY}"
```

`X-API-Key` と `Authorization` ヘッダーを同時に送信すると拒否されます。

## 主な操作と必要な権限

別の連携用 API を作る必要はありません。既存の `/api` エンドポイントに対して正規の管理権限が適用されます。

| 操作 | API | Canonical Permission |
| --- | --- | --- |
| Custom Tools の一覧 | `GET /api/CustomSqlTool` | `/runtime/custom-tools.view` |
| Custom Tool の作成 | `POST /api/CustomSqlTool` | `/runtime/custom-tools.create` |
| Custom Tool の公開 | `POST /api/CustomSqlTool/{id}/publish` | `/runtime/custom-tools.edit` |
| アクセスキーの一覧 | `GET /api/runtime/mcp-keys` | `/runtime/mcp-keys.view` |
| アクセスキーの発行 | `POST /api/runtime/mcp-keys` | `/runtime/mcp-keys.create` |

## 権限とキーの管理

連携に必要な権限だけを付与してください。管理者はキーをいつでも失効させることができ、ローテーション時には新しい秘密値を発行して古いキーを即時無効化します。管理 DB に残るのはハッシュであり、操作は `management-api-key` として監査されます。

管理 API キーの発行・ローテーション・失効には、ログイン済み管理者の `/runtime/security.edit` 権限が必要です。

> 管理権限は特定のデータベース ID やテナントに自動では限定されません。信頼できるバックエンドにキーを保管し、アプリケーション固有の認可は連携側で実装してください。

## 導入に必要な準備

キーを発行する前に、SQLite または PostgreSQL 用の Admin Store マイグレーションで `ManagementApiKeys` テーブルを追加します。
