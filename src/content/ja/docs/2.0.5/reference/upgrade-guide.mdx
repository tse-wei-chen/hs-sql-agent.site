## 2.0.5 の変更点

2.0.5 では、5 個の組み込み MCP ツールの公開結果契約が、表示文字列中心の形式から型付きの構造化結果へ変わります。SQL コンパイラ、テーブル認可、DML 承認モデル、トランザクション所有、MCP キーの既定の安全姿勢は緩和されません。

組み込みツールは引き続き `get_schemas`、`get_tables`、`get_columns`、`execute_query_sql`、`execute_dml_sql` の 5 個です。

## クライアント移行

ツール出力を表示するだけのクライアントは通常そのまま利用できます。自動処理が出力文字列を解析している場合は、MCP `structuredContent` と推論された出力スキーマの正式フィールドを利用してください。

`execute_query_sql` では `Success`、`Provider`、`RowCount`、`DurationMs`、`Rows`、`Error` を直接読みます。表示文字列から行数や JSON を抽出しないでください。

メタデータ系ツールでは `Schemas`、`Tables`、`Columns` を直接利用します。テーブル／カラムに許可されたセマンティックメタデータが明示的な入れ子フィールドとして含まれます。

失敗処理はメッセージの接頭辞ではなく `McpToolError.Code`、`Stage`、`Retryable` で判定してください。`Message` は表示やログには使えますが、安定した制御フィールドではありません。

## DML 状態の移行

`execute_dml_sql` の `Status` は次の 4 種類です。

| `Status` | 意味 | `Committed` | `Error` |
| --- | --- | --- | --- |
| `committed` | 承認されコミット済み | `true` | null |
| `pending` | 外部承認待ち | `false` | null |
| `rejected` | 承認拒否 | `false` | null |
| `failed` | ポリシー、検証、同時実行、設定、実行の失敗 | `false` | 設定あり |

`pending` と `rejected` は通信エラーや実行エラーではなく、有効な承認結果です。

非同期承認では `ApprovalRequestId` を保存または関連付けてください。承認プロバイダーが外部参照を返す場合は `ApprovalExternalReference` も利用できます。`pending` の時点では DB 変更はコミットされていません。

対応 DML が `RETURNING` などの結果句を使用する場合は、`Message` の解析ではなく `ReturnedRows` からコミット済み行を取得してください。

## 変わらないもの

- 新規 MCP キーでは 4 個の読み取り／クエリツールが引き続き既定で選択されます。
- `execute_dml_sql` は引き続きオプトインです。
- 未対応 SQL は引き続き fail closed です。
- テーブル許可リストとツール認可はサーバー側で強制されます。
- 複数 DML は 1 回承認され、サーバー所有の単一原子トランザクションで順番に実行されます。
- durable な `pending` 承認は、後続コミット前に現在の認可、設定、ポリシー、計画、row-set、影響行数の証拠を再検証します。
- クライアント提供のトランザクション制御 SQL は拒否されます。

## ロールバック

2.0.4 に戻すと、組み込みツールは以前の結果形式に戻ります。段階的な展開で両バージョンを同時に扱う必要がある場合、構造化フィールドだけを読むクライアントはサーバーバージョンを考慮してください。

この構造化結果の変更自体に DB スキーマや SQL 定義の移行は不要です。

正確なフィールドは [MCP ツールリファレンス](/ja/docs/mcp/tools-reference)を参照してください。
