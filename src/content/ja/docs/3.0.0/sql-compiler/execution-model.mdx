## コンパイル制限とスキーマ証拠

4,194,304 UTF-16 単位、131,072 個の End 以外の字句トークン、8,192 段のグループ化、65,536 AST ノードのいずれかを超える入力は拒否されます。反復型 AST 走査と上限付きレンダリングは、6 プロバイダーでパラメーター順序と安全性を証明できない場合の拒否を維持します。任意の SQL 深度を保証するものではありません。

上限はステージごとに 8,000,000 作業単位、コンパイル全体で 32,000,000 作業単位、ステージごとに 30 秒、全体で 90 秒、ステージごとの累積マネージド割り当て 536,870,912 バイトです。DB クエリのタイムアウトやプロセスメモリ上限ではなく、コンパイル予算です。超過は型付きリソース診断で報告されます。

任意で有効にする不変スキーマスナップショットは、テーブル・列名、証明可能な型ファミリー、順序付き CTE／派生投影を解決し、ダイジェストを計画フィンガープリントに結び付けます。完全な DB 型チェッカーではありません。スキーマ証拠付き DML にはライブの鮮度検証が必要で、証拠の欠落・変更時は拒否されます。既定ではスナップショットを取得しません。`AddHsSqlAgentNativeDmlSchemaFreshness()` でネイティブサポートを明示的に有効化できます。

hs-sql-agent は、AI が生成した SQL をそのまま信頼済みコマンドとして扱いません。実行前に解析、検証、対応能力の確認、アクセスポリシーの適用、接続先データベース向けのコンパイルを行います。

## クエリの実行経路

クエリは大きく次の順序で処理されます。

1. MCP キーを認証し、そのキーに設定されたデータベース、テーブル、ツール、実行上限を適用する。
2. 対応している SQL を構造化された定義 / AST へ解析する。
3. 文と入力側 SQL の意味がサポート範囲内にあるか検証する。
4. 同じ意味を保つために必要な機能を、接続先データベースが安全に表現できるか確認する。
5. 設定されたデータベース向けに SQL をコンパイルして出力する。
6. 設定された実行上限の範囲内で SQL を実行する。

SQL コンパイラには、入力側の意味を検証する段階と、出力先の対応能力を確認する段階が明示的に分かれています。対応していない構文や、安全に同じ意味を表現できると確認できない機能は、見た目だけ似た別の構文へ置き換えずに拒否します。

## なぜフェイルクローズなのか

複数のデータベースで SQL を扱うと、見た目が似ていても NULL の扱い、型規則、演算子の意味、ページング、識別子、関数、DML の動作が異なる構文が数多くあります。

AI から SQL を受け付ける実行基盤で「可能な範囲で書き換える」方式を採ると、構文としては正しくても意味が変わる危険があります。hs-sql-agent はそのため、暗黙の意味変更よりも明示的な拒否を選びます。

## データベースごとの SQL 出力

MCP の公開インターフェースは共通ですが、最終的に生成される SQL はデータベースごとに異なります。現在対応しているデータベースは次のとおりです。

- PostgreSQL
- MySQL
- SQL Server
- Oracle
- SQLite
- Firebird

対応範囲は意図的に限定されています。データベース自体が対応一覧にあるからといって、その製品が提供するすべての SQL 構文を受け付けるわけではありません。個々の機能は、その意味を内部表現として保持し、検証できるようになった段階で追加されます。

## GROUPS によるウィンドウフレーム

PostgreSQL 11 以降と SQLite 3.28 以降では、`SUM(amount) OVER (ORDER BY grp GROUPS BETWEEN 1 PRECEDING AND CURRENT ROW)` のようなウィンドウフレームをコンパイルできます。`GROUPS` は並び替えキーが等しい行の集まりを単位として数えます。個々の行を数える `ROWS` や値の範囲を扱う `RANGE` とは意味が異なります。ウィンドウ内の明示的な `ORDER BY` が必須です。不正なフレーム境界や、対応開始バージョンより古いと明示されたデータベースは拒否し、別のフレーム単位には暗黙変換しません。MySQL、SQL Server、Oracle、Firebird ではこの機能を許可しません。実行前にホスト側で実際のデータベースのバージョンを検証する必要があります。

## EXCLUDE：ウィンドウフレームからの行の除外

PostgreSQL 11 以降と SQLite 3.28 以降では、`ROWS`、`RANGE`、`GROUPS` のフレームに四種類の除外指定を追加できます。`EXCLUDE CURRENT ROW` は現在行のみ、`EXCLUDE GROUP` は現在行と同じ並び替えキーの行すべてを除外します。`EXCLUDE TIES` は現在行を残して同じキーの他の行を除外し、`EXCLUDE NO OTHERS` は何も除外しません。例：`SUM(amount) OVER (ORDER BY grp GROUPS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW EXCLUDE TIES)`。`ROWS` を指定した場合も、除外時には同じ並び替えキーの行を考慮します。F# コンパイラーと `WindowFrameDefinition.Exclusion` は意味を変えずに扱います。明示された旧バージョンや他の四種類のデータベースは拒否されます。実行前には Host が実際のデータベースバージョンを確認する必要があります。

## SQL Server の RANGE フレームにおける数値オフセット制限

SQL Server の T-SQL 構文では、`RANGE` ウィンドウフレームに数値付きの `PRECEDING` または `FOLLOWING` を指定できません。たとえば `RANGE BETWEEN 1 PRECEDING AND CURRENT ROW` は、出力先を PostgreSQL や SQLite に指定していても、**SQL Server の入力構文として無効**なため拒否されます。有効な `ROWS` のオフセットと `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` は引き続き利用できます。PostgreSQL と SQLite 固有の数値 `RANGE` の意味は維持されます。コンパイラーは入力方言の適合性と出力先の対応能力を別々に検証し、出力先で使える構文を入力構文の有効性の根拠にはしません。
